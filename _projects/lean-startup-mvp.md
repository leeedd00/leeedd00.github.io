## 배경

2025 동남권 린스타트업 스쿨은 아이템을 짧은 기간에 MVP로 검증하는 프로그램입니다. 팀 Autoful은 소상공인(식품업 중심)의 재고관리 · 발주 업무를 모바일로 반자동화하는 앱을 아이템으로 잡았고, 프로그램의 외주 용역비로 안드로이드 MVP 제작을 발주했습니다. 이 프로젝트에서 저는 개발자가 아니라 **발주자 · 기획자** 역할이었습니다.

## 과업지시서

MVP에 꼭 필요한 기능만 골라 요구사항을 문서로 정의했습니다.

| 구분 | 요구사항 |
|------|----------|
| 기능 | 식자재 가격 확인 모듈 (KAMIS 농산물 시세 API 연동) |
| 기능 | 원클릭 발주 — 재고 수량에 따라 색상으로 안내, 주문 버튼을 누르면 해당 업체에 주문 문자 발송 |
| 기능 | 챗봇형 고객응대(Keeping Bot) UI |
| 기능 | 관리자 백오피스(웹 대시보드) |
| 인터페이스 | 상품 등록 · 입출고 · 재고 현황 UI, 홈 화면과 재고관리 페이지 |
| 데이터 · 보안 | 행정DB 표준화 지침에 따른 데이터 품질 관리, 소프트웨어 개발보안 가이드(시큐어코딩) 준수 |
| 제약 · 지원 | 산출물 소유권과 지식재산권 공동 소유, 무상 하자보수 1개월, 하자 발견 시 24시간 내 조치 |

## 진행

- 2025.11 과업지시서 작성 → 개발사(백슬래시파트너스) 계약
- 2025.12.01 – 04 앱 개발, 12.04 – 05 피드백 반영 · 수정
- 결과보고서 검토, 안드로이드 APK 설치파일과 원본 소스코드 인수, 1주 유지보수 지원 확인

## 배운 점

- **요구사항 문서가 결과물 품질을 좌우합니다.** 일정이 짧을수록 "무엇을 만들지"를 표로 정확히 써 두는 것이 개발만큼 중요했습니다. 모호하게 적은 항목은 그대로 모호하게 나왔습니다.
- **개발자 입장을 알면 발주가 쉬워집니다.** 같은 시기 [Keeping 1차 웹 버전](/projects/keeping-web/)을 직접 만들고 있어서, 구현 난이도를 감안해 MVP 범위를 자를 수 있었습니다.
- 이 경험과 웹 버전을 합쳐 2026년 [Keeping 2차 모바일 앱](/projects/keeping/)의 PRD를 직접 썼습니다.
